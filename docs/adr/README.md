# Architecture decision records

Record durable decisions that constrain future implementation. Create an ADR only after
the decision and its tradeoff are confirmed. Initialization adds the structure, not
speculative architecture choices or a duplicate of the delivery contract.

Use sequential filenames, `NNNN-kebab-case-title.md`. Each ADR contains:

- Title
- Status: proposed, accepted, superseded, or rejected
- Context
- Decision
- Consequences
- Supersedes / Superseded by, when applicable

`CONTEXT.md` owns confirmed terms and ownership. Issues own delivery requirements and
acceptance criteria. An ADR records rationale, not a second acceptance contract.
